Architecture Analysis: Attendance System & Future IoT Integration

Technical report covering existing QR implementation review, GPS Geo-fencing anti-spoofing measures, and hardware-agnostic IoT integration points.

1. Review of Current QR Code & GPS Location Mechanism

The legacy and current system uses a Time-Based Rotating Dynamic QR Code + Browser GPS Geo-Fencing:

  • Payload: Compact JSON with hr_id, Unix epoch timestamp, and action identifier type: "hr_qr".
  • Rotation Interval: Refreshes every 5,000ms (5 seconds) to ensure codes cannot be photographed and shared.
  • Expiration Validation: Validates Math.abs(Date.now() - token.timestamp) < 40 seconds.
  • Geo-Fencing Verification: Calculates distance using the Haversine formula from company coordinates (Lat: 30.0444, Lng: 31.2357). Enforces a 500-meter radius boundary.
  • Database Storage: Each successful punch logs to the attendance table, recording check_in, check_out, check_in_location with GPS coordinates, and single-use token in qr_tokens.

2. Future IoT Integration Blueprint (Hardware-Agnostic)

Without assuming proprietary hardware or locking the company to a specific vendor before board approval, the architecture prepares the following integration interfaces:

A. Device Types Supported

Biometric Fingerprint scanners (e.g. ZKTeco, Anviz), RFID/NFC Turnstiles, or ESP32-based industrial relays.

B. Ingestion Protocol

Industrial Edge Broker using MQTT or HTTPS Webhooks with mutual TLS / API bearer tokens.

C. Offline Buffer Resilience

Local SQLite edge cache buffering timestamps during factory WAN outages, syncing automatically upon restoration.

Standard REST Endpoint Contract for Future IoT Devices:
